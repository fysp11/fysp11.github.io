## 2024-05-18 - Astro Image Processing & React Boundaries
**Learning:** In Astro, the built-in `<Image />` component from `astro:assets` cannot be used inside React UI components (.tsx). Attempting to do so results in unoptimized images or build errors. Furthermore, when using `getImage()` at the Astro level to pre-compute optimized images located in `/public`, a simple string path is insufficient for the `src`; the images must first be resolved as `ImageMetadata` using `import.meta.glob<{ default: ImageMetadata }>("/public/...")`. Finally, indiscriminately using `loading="lazy"` on above-the-fold images causes performance regressions (LCP delay); they must use `loading="eager"` and `fetchpriority="high"`.
**Action:** When working with dynamic images passed to React components in Astro, use `import.meta.glob` to resolve the images in the `.astro` server block, pass the resolved modules to `getImage()` to compute WebP URLs at build time, and pass those string URLs as props to the React component which renders standard `<img>` tags. Apply `loading="eager"` and `fetchpriority="high"` strictly to above-the-fold elements (e.g., the first two items in a list/grid) and `loading="lazy"` to the rest, along with `decoding="async"` to prevent main-thread blocking.
