## 2025-02-20 - [Information Leakage] Prevent Sensitive Data Exposure in API Routes
**Vulnerability:** External API payloads (Google AI Studio text responses), raw execution configurations, and internal generic unhandled exceptions (stack traces/messages) were being returned directly to the client in catch blocks and error handling paths within API routes.
**Learning:** Directly proxying external provider responses or internal exception messages back to the client can leak sensitive details like API configurations, prompt injections, payload schemas, and internal environment issues. This increases the attack surface for malicious actors targeting the AI features.
**Prevention:** Always log detailed error messages, external text responses, and unexpected behaviors server-side using `console.error` for debugging. Return only sanitized, generic JSON error messages (e.g., `error: "Internal error"`) to the client without exposing the underlying failure details or proxy responses.
