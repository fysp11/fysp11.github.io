## 2026-10-12 - Prevent Information Disclosure in API Routes
**Vulnerability:** API routes (`src/pages/api/*.ts`) were directly passing raw error objects, stack traces, internal status text, or infrastructure configuration details (such as missing cloudflare bindings) in JSON responses back to the client.
**Learning:** Returning detailed error objects to the client provides attackers with insights into the internal architecture, dependencies (like `@cf/meta/llama-3.1-8b-instruct`), and failure states, which is an information disclosure vulnerability. It occurred because catch blocks and failure paths were returning the raw `error.message` or `result` object for debugging purposes instead of safely sanitizing them for the client.
**Prevention:** Always follow the "Fail securely" principle. Log raw errors, exceptions, and upstream response bodies server-side using `console.error` for debugging, but only return generic, sanitized string messages like "Internal server error" or "Invalid response" to clients in HTTP responses.
